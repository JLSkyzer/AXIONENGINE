# ADR-139 — Le jeu fournit au compilateur les fichiers voisins qu'il demande (R-830, IF-06, ABI 4)

- **Statut** : **accepté** — le protocole « demande puis renvoi » et les fichiers gardés en mémoire
  sont tranchés par Killian le 2026-10-15 ; les détails ci-dessous sont de Claude.
- **Date** : 2026-10-15
- **Portée** : R-830, R-860 (CLI identique au jeu) ; IF-06 (`axion_asset_compile`,
  `axion_asset_poll`) ; ABI 3 → 4 ; C-20 (registre, source), C-25 (clé du cache) ; R-531, R-533
- **Constat d'origine** : ADR-122, constat 5 ; audit de la DoD de M2 (2026-10-15)

## Contexte

La compilation en jeu passait `|_| None` au résolveur des fichiers voisins : un OBJ y perdait son
`.mtl` sans le dire, un glTF à buffer externe y était refusé, alors qu'`axion-cli` lisait les deux.
Le compilateur ne lit que ces deux sortes de voisins : **les buffers externes d'un glTF** et **les
`.mtl` d'un OBJ**. Les images ne sont jamais lues — une image à URI externe est un chemin relatif dans
`TEXR` (ADR-122, R-532).

Le jeu ne peut pas savoir d'avance ce qu'une source référence sans l'analyser, et l'analyser en Java
serait un second lecteur, que R-830 interdit. Le gestionnaire de ressources n'est plus valide après le
rechargement : Java ne peut servir plus tard que ce qu'il a lu pendant.

## Décision

### 1. Java garde les voisins possibles

À l'énumération, `ResourceAssetSource` lit, en plus des sources et des `.axion.json`, **tout fichier sous
`axion/models/` qui n'est pas une image** (`png`, `jpg`, `jpeg`, `ktx2`, `webp`) — aucun nom ni
extension de buffer n'est supposé (glTF les laisse libres) —, **borné par `assets.max_source_bytes`** :
un voisin plus grand reste énuméré, mais il n'est pas lu, pour qu'un fichier volumineux posé parmi les
modèles ne soit pas retenu en mémoire à chaque rechargement. Sa lecture échoue comme celle d'une
ressource illisible : signalé au journal, il part absent si une source le demande. La borne ne touche
pas les sources, dont le compilateur juge la taille lui-même (R-533, `E-3005`).

Un voisin illisible part absent, comme dans `axion-cli` dont la lecture échoue (R-830) ; l'asset n'échoue
pas pour autant, au contraire d'un `.axion.json` illisible (ADR-135).

### 2. Le compilateur demande, Java renvoie

- `axion_asset_compile(ctx, asset_id, source_format, source_len, files_len, options_cbor, options_len,
  out_job_id)` : `files_len` octets suivent la source dans `ASSET_IN`, une **table de fichiers**
  (vide, `files_len` = 0, à la première soumission).
- Dans le travail, le résolveur cherche chaque référence, **normalisée** (§3), dans la table : présent,
  il rend ses octets ; marqué absent, il rend « rien », comme la CLI dont la lecture échoue ; inconnu, il
  **note le nom** et rend un contenu vide provisoire, pour que l'importeur continue et demande tout le
  reste dans le même passage.
- Si un nom a été noté, le résultat du passage est jeté et le sondage rend le statut **`NEEDS_FILES`**
  (3) : `ASSET_OUT` porte la liste des noms, triée, sans doublon ; `out_size` sa longueur.
- Java renvoie la source **avec** la table : chaque nom demandé, présent avec ses octets, ou marqué absent
  s'il ne l'a pas. Le second passage compile comme la CLI. Une demande de noms nouveaux reste possible
  (un format futur qui chaînerait ses références) : Java y répond de même, **quatre passages au plus**,
  puis l'asset échoue.
- `NativeAssetCompiler` mène ce dialogue seul : le registre, et la machine à états SM-01, voient un
  travail qui continue.

Table de fichiers (petit-boutiste, comme les tampons de transfert, R-271) :

```text
u32 count                      au plus 256
répété count fois :
  u32 name_len                 1 à 1024 octets, UTF-8, nom normalisé (§3), sans doublon
  u32 flags                    0 présent, 1 absent
  u64 data_len                 0 si absent
  u8  name[name_len]
  u8  data[data_len]
```

Liste de `NEEDS_FILES` : `u32 count`, puis par nom `u32 len` et ses octets UTF-8.

Une table mal formée — bornes, nom non normalisé, doublon, drapeau inconnu — refuse la soumission
(`AXION_E_INVALID_BUFFER`).

### 3. Une seule règle de nom

`ax_asset::import::normalize_reference` : chemin relatif sous le répertoire de la source, séparé par
`/` ; refusés : `\`, une lettre de lecteur, une racine, `..` ; `.` et les segments vides tombent. La CLI
(`sibling_path`) et le jeu l'appellent tous deux : le même nom désigne le même fichier des deux côtés.
Côté Java, un nom normalisé se résout en `<répertoire de la source>/<nom>` ; Minecraft n'admettant que
`[a-z0-9/._-]` dans un chemin de ressource, un nom hors de cet alphabet n'y existe pas et part absent.

### 4. La clé du cache voit les voisins

Le terme « contenu » de R-892 devient la source **et ses voisins possibles** : tout fichier gardé (§1)
sous le répertoire de la source, triés par chemin, chacun par son nom, sa longueur et ses octets ; un
voisin non lu (illisible, ou au-delà de la borne) par son nom et une longueur de -1, pour que la source
se recompile le jour où il se lit.
Un `.mtl` ou un `.bin` modifié recompile les sources de son répertoire ; un fichier ajouté aussi. Le
compte est large — un voisin non référencé invalide quand même —, mais jamais faux.

### 5. ABI 4

Signature d'`axion_asset_compile`, statut `NEEDS_FILES`, table : rupture binaire, `AXION_ABI_VERSION`
et `EXPECTED_ABI_VERSION` passent à 4 (R-261).

## Conséquences

- R-830 tient pour les fichiers voisins : `asset_options_abi` et un test dédié comparent, au bit près,
  l'asset compilé par ce dialogue à celui que la CLI compile des mêmes fichiers.
- Reste `asset_id`, que la CLI dérive du nom de fichier faute d'espace de noms : avec R-861 (C-20).
- Un voisin au-delà d'`assets.max_source_bytes` part absent, et un voisin plus grand que le tampon
  `ASSET_IN` ne peut y tenir : la soumission échoue. Dans les deux cas la CLI, elle, lirait le fichier.
  Cas limites, non rencontrés, nommés ici.
- Un travail que le registre cesse d'attendre — source modifiée ou retirée, recompilation forcée,
  délai de démarrage écoulé — est abandonné au compilateur (`AssetCompiler.abandon`), qui oublie la
  source et les voisins qu'il gardait pour un nouveau passage. Le natif l'oublie aussi depuis
  [ADR-140](ADR-140.md) (`axion_asset_cancel`) ; avant, son résultat restait dans le contexte
  jusqu'à l'arrêt.
