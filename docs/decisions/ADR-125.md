# ADR-125 — Attribution des tests T-370..T-375 (C-38) et T-380..T-384 (C-39)

- **Statut** : **proposé** — à ratifier par Killian.
- **Date** : 2026-10-06
- **Portée** : fiches 5.30 (C-38) et 5.31 (C-39), R-640..R-643, R-650..R-652, PARTIE 37.2
  (acceptance de M3)
- **Proposé par** : Claude, pour la tranche C de l'acceptance de M3

## Contexte

Les fiches ne donnent que des plages : « Tests. T-370..T-375 » pour C-38, « Tests. T-380..T-384,
T-856 » pour C-39 ; l'acceptance de M3 les reprend. ADR-123 §12 a attribué de la même façon
T-300..T-307 à C-31. L'inventaire du 2026-10-06 ne trouvait aucun de ces identifiants dans le code,
alors que l'essentiel des comportements était testé : des tests sans nom d'acceptance ne se
comptent pas.

## Décision proposée

Chaque identifiant reçoit une exigence ; les tests qui la réalisent le portent — préfixe `t37x_`
ou `t38x_` des tests natifs, Javadoc des classes de test Java, Javadoc des GameTests.

### T-370..T-375 — C-38, World Collision Provider

| Test | Exigence | Réalisé par |
|---|---|---|
| T-370 | Étape 2 : une tuile est une liste compacte de boîtes quantifiées au 1/16, relatives à sa section, blocs pleins fusionnés | `WorldTileGeometryTest` (adressage, quantification, fusion) |
| T-371 | Étape 3 : tuiles posées par lot en compounds statiques d'au plus 64 boîtes, remplacées et retirées ; un corps y repose ; même résultat d'une exécution à l'autre | `sim.rs`, `t371_*` ; `WorldTileServiceTest` |
| T-372 | Étape 4 : tout changement de bloc invalide sa tuile ; reconstruction amortie à `world.tiles_per_tick`, ce qu'un corps occupe en tête | `WorldTilePlannerTest` ; GameTest `unBlocRetireSousUnCubeLeLaisseTomber` |
| T-373 | Étape 5 : libération des tuiles sans assembly dans `world.tile_radius` | `WorldTilePlannerTest`, `WorldTileServiceTest` |
| T-374 | R-640 : une section non chargée est pleine et solide, sans chargement de chunk ; R-641 : au-delà de 4096 boîtes, champ de hauteurs conservateur, avec avertissement | GameTests `CollisionDuMondeGameTests` (fournisseur Forge, vrai monde) ; `WorldTileGeometryTest` (seuil) ; `sim.rs`, `t374_*` |
| T-375 | R-642 : les fluides sont des volumes de flottabilité ; R-643 : matériau dominant résolu par données | `WorldTileGeometryTest` (eau), `BlockMaterialsTest` ; `sim.rs`, `tests/world.rs` et `tests/chute_dans_l_eau.rs`, `t375_*` |

## Limites

- R-651 vise une requête faite **depuis Java** pendant la fenêtre de simulation ; aucune API Java
  de requête n'existe encore. T-384 en vérifie la moitié native : une requête lit le monde que le
  dernier pas a laissé.
- R-641 demande un avertissement : il manquait, et le fournisseur Forge le journalise désormais,
  une fois par section. Le GameTest de T-374 ne le vérifie pas lui-même ; son passage du
  2026-10-06 en a journalisé exactement un, pour la section qu'il découpe.

## Conséquences

- L'inventaire de l'acceptance de M3 se fait mécaniquement : chaque identifiant se retrouve dans
  le code avec les tests qui le réalisent.
- Un test qui en réalise un garde son préfixe ou sa mention ; le renommer sans eux le ferait
  disparaître de l'inventaire.
