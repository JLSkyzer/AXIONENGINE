# ADR-102 — Une configuration refusée est signalée par `E-2002`

- **Date** : 2026-09-10
- **Statut** : accepté
- **Portée** : `ax-ffi`, `ax-model`, C-04
- **Références** : R-443, obligation 4.8, ANNEXE A.1, DM-19

## Contexte

`axion_init` reçoit la configuration encodée en CBOR et la revalide contre le
registre : chemin déclaré, type correct, valeur dans son domaine. Ce refus doit
être rendu à Java sous forme de code d'état.

L'ANNEXE A.1 recense quarante codes d'erreur. **Aucun ne couvre une
configuration invalide.** Les plus proches concernent le bootstrap
(`E-1001` Forge hors plage, `E-1002` ABI incompatible), le natif (`E-1003`,
`E-1004`), les definitions data-driven (`E-7001`), ou les données reçues à la
frontière (`E-2002`, « tampon invalide ou périmé », domaine ffi).

L'implémentation initiale de M0.2 avait attribué `E-1005` et `E-1006` à ce cas.
Ces codes n'existent pas. Le test T-023 les a relevés dès qu'il a été écrit.

## Décision

Une configuration refusée par le natif renvoie **`E-2002`**.

Le type d'erreur interne du registre de configuration ne porte plus de code du
tout : les codes de l'ANNEXE A.1 sont des codes d'**ABI**, produits à la
frontière, et non des étiquettes attachées à chaque erreur interne.

## Justification

L'obligation 4.8 impose que tout nouveau code d'erreur soit ajouté à l'ANNEXE
A.1. Le cahier des charges étant gelé, cette voie est fermée : inventer `E-1006`
revenait à étendre l'annexe sans y toucher, et à produire un code qu'aucun
utilisateur ne pourrait rechercher.

Restaient deux options. Ne renvoyer aucun code distinctif aurait rendu le refus
indiscernable d'une autre erreur. Réutiliser un code existant demandait qu'il
soit sémantiquement juste : `E-2002` l'est. La configuration arrive de Java à
travers la frontière, sous forme d'une charge utile CBOR ; une charge utile que
le natif refuse est exactement ce que ce code décrit, dans le domaine ffi qui
est bien celui où le refus a lieu.

La règle de gestion de l'incertitude du contrat d'implémentation demande
l'option la plus conservatrice pour la correction, accompagnée d'un ADR. Ne rien
inventer est cette option.

## Conséquences

- Java distingue une configuration refusée d'un contexte déjà ouvert
  (`E-1004`) ou d'une ABI incompatible (`E-1002`), mais pas d'un tampon invalide.
  Le message porté par `axion_last_error` lève l'ambiguïté, et c'est lui que
  le journal affiche.
- Si une révision ultérieure du cahier des charges ajoute un code propre à la
  configuration, `AXION_E_CONFIG` change de valeur sans que rien d'autre bouge :
  la constante existe précisément pour cela.
- T-023 garde le dépôt honnête : tout `E-xxxx` cité dans le code, en Java comme
  en Rust, doit figurer dans l'annexe.
