# ADR-137 — La Definition of Done de M2 se prononce sur un périmètre borné, composant par composant

- **Statut** : **accepté** — ratifié par Killian le 2026-10-16, tel qu'il est après les quatre tours de
  décisions des 2026-10-15 et 2026-10-16 (le principe d'un ADR de portée était tranché le 2026-10-15).
- **Date** : 2026-10-15
- **Portée** : §37.3 (« Composant terminé », « Jalon terminé ») ; jalon M2 (C-23, C-25, C-27, C-30, C-50,
  C-70, C-72, C-74) ; PARTIE 5 (fiches des huit composants)
- **Proposé par** : Claude, à la suite de l'audit de la Definition of Done de M2 du 2026-10-15

## Contexte

La DoD de 37.3 veut chaque composant « terminé » : fiche PARTIE 5 respectée, tests verts, métriques,
budget, modes de défaillance, fallback, documentation. L'audit du 2026-10-15 (trois sous-agents en lecture
seule, critère par critère, consigné dans `tasks/todo.md`, section « Clôture de M2 ») conclut qu'aucun des
huit composants ne la tient. Ce verdict mêle deux choses de nature différente :

1. des **défauts** — une exigence que M2 pouvait tenir et ne tenait pas (cache sans plafond, zstd au
   niveau 3, `/axion bench --json` sans confinement, `test_cube` livré). Ils se corrigent ;
2. des **parts de fiche qui dépendent de systèmes à venir** — une fiche STABLE de M2 qui décrit aussi ce
   que fera C-35 (M6), C-53 (M5) ou C-28 (M6). Aucun travail en M2 ne peut les tenir sans bouchon, ce que
   R-001 interdit.

Le CDC classe ces composants STABLE en M2 sans dire comment lire leur DoD quand leur fiche déborde le
jalon. Killian a tranché le 2026-10-15 qu'un ADR la borne, comme ADR-134 l'a fait pour T-630..T-634.

## Décision proposée

La DoD de M2 se prononce sur ce que **M2 tient** (colonne 2). Ce qui **part** (colonne 3) quitte la DoD de
M2 et entre dans celle du jalon nommé, avec le test qui le prouvera ; chaque jalon le reprend dans sa propre
DoD. Ce qui **reste** (colonne 4) se fait avant de prononcer M2.

## Conséquences

- La DoD de chaque jalon de M3 à M7 reprend les lignes de la colonne 3 qui le nomment : un renvoi n'est
  pas un oubli, c'est une ligne de la DoD suivante.
- Aucun bouchon n'entre dans le code pour faire passer une case de M2 (R-001) ; ce qui ne peut pas être
  réel attend son jalon.
- L'audit reste la référence de détail ; cet ADR n'en recopie que la décision.

## Amendement A1 (Killian, 2026-10-16) — les avertissements de compilation en jeu

**Constat de Claude, 2026-10-16.** Les avertissements d'une compilation (`CompiledAsset.warnings` :
extension glTF de `extensionsUsed` ignorée, R-530 ; extras invalide, R-912 ; forme de collider signalée
sans être produite, C-32) sont collectés côté natif puis **jetés au sondage** (`axion_asset_poll`) : ils
n'atteignent ni Java ni aucun journal du jeu. Seule la CLI les affiche. Aucune ligne de cet ADR ne les
renvoyait : le reliquat figurait dans `tasks/todo.md` (C-74, tranche 7 d'ADR-135) sans jalon.

Ce n'est pas un défaut de l'importeur (C-21, M1) : il produit l'avertissement. C'est le chemin en jeu qui le
perd. Le corriger touche la frontière FFI — une fonction ajoutée ou un tampon dédié — et demande un ADR,
en effort maximal ; il n'existe aucun canal de journal du natif vers Java.

**Décision (Killian : renvoyer par amendement).** Le reliquat quitte la DoD de M2 et entre dans celle de
**M3, avec C-32** : C-32 est le premier composant dont les avertissements doivent atteindre l'auteur (R-912,
une forme de collider non prise en charge s'avertit), et la remontée se décide avec lui, par un ADR de
frontière. Preuve attendue : une source qui provoque un avertissement connu le fait apparaître dans le
journal du jeu, une fois par compilation.

**Précision de Claude, à lire comme telle :** le jalon M3 plutôt que M4 est la lecture de Claude ; Killian
a tranché le renvoi, pas le jalon, et peut le déplacer.
