# ADR-141 — Tests de M2 que le CDC ne décrit que par plages : T-240..T-244, T-280..T-284, T-400..T-404

- **Statut** : **accepté** — la table, et l'écriture des tests de R-581 et R-701, ratifiées par
  Killian le 2026-10-15 sur la fiche de décision ; le texte est de Claude.
- **Date** : 2026-10-15
- **Portée** : liste des tests de M2 (PARTIE 37.2) ; fiches 5.16 (C-23), 5.20 (C-27) et 5.41 (C-50)
- **Précédent** : ADR-128, pour des tests de M3

## Contexte

Les fiches de C-23, C-27 et C-50 ne nomment leurs tests que par plages — « T-240..T-244 »,
« T-280..T-284 », « T-400..T-404 » — et la liste de M2 les reprend telles quelles. Seul T-243 est décrit
(R-553). L'audit de la DoD de M2 a relevé que l'attribution de chaque numéro n'était consignée nulle part,
sinon dans les tests eux-mêmes, et qu'aucun test ne citait R-581 ni R-701.

## Décision

Chaque numéro désigne le groupe de tests qui le porte dans son nom (`t240_…` en Rust, `@DisplayName("T-280 : …")`
en Java). La table fixe ce que chaque groupe prouve, telle que le code la porte au 2026-10-15.

| Test | Ce qu'il prouve | Où |
|---|---|---|
| **T-240** | Fusion des sommets identiques (positions, normales, ±0), sans traverser les meshes ; plage des UV par mesh | `ax-asset` : `optimize/merge.rs`, `optimize/uv.rs`, `compile.rs` |
| **T-241** | Normales pondérées par l'angle, jamais recalculées si écrites | `optimize/normals.rs` |
| **T-242** | Boîtes englobantes des meshes et de l'asset, arrondi vers l'extérieur | `optimize/bounds.rs`, `compile.rs` |
| **T-243** | Optimizer déterministe au bit près, à plateforme égale (R-553, ADR-106) | `optimize/mod.rs` |
| **T-244** | Tangentes MikkTSpace et cache de sommets | `optimize/tangents.rs`, `optimize/cache.rs` |
| **T-280** | JSON strict : UTF-8, doublons, tolérances de Gson, imbrication, nombres | `StrictJsonTest` |
| **T-281** | Schéma versionné, refus individuel (R-580), empreinte, asset et kind | `DefinitionRegistryTest` |
| **T-282** | Structure du schéma 1 : types, listes fermées, plages, clés inconnues hors `custom` | `DefinitionSchemaTest` |
| **T-283** | Références internes et noms : unicité, cycles, sources de l'ANNEXE A.4 | `DefinitionSchemaTest` |
| **T-284** | Schéma publié (`docs/schema/definition-1.json`) et definitions du dépôt conformes | `PublishedSchemaTest` |
| **T-400** | Identifiant 64 bits d'une definition (FNV-1a), collision refusée (E-3010) | `DefinitionIdsTest` |
| **T-401** | Création par commande, plafond de R-811 | `AssemblyEntityRulesTest` |
| **T-402** | Liaison au chargement ; definition inconnue ou schéma autre → inerte (R-704) | `AssemblyEntityRulesTest` |
| **T-403** | NBT : clés d'AXION écrites, clés étrangères conservées, schéma postérieur réécrit tel quel | `AssemblyTagsTest` |
| **T-404** | Données d'apparition : aller-retour, bornées | `AssemblyTagsTest` |

Deux exigences des mêmes fiches n'avaient pas de test ; elles en reçoivent un, rattaché au groupe de leur
composant :

- **R-581** (C-27, avec T-280..T-284) : une definition ne peut déclencher aucune exécution de code —
  `DefinitionCodeExecutionTest` lit le bytecode de `dev.axion.definition` et n'y admet aucune porte vers du
  code désigné par une donnée (réflexion, chargement de classe, scripts, processus) ;
- **R-701** (C-50, avec T-400..T-404) : `tick()` n'exécute aucune physique — `EntityTickPhysicsTest` suit le
  graphe d'appels depuis `AxionEntity.tick()` et ses redéfinitions de Minecraft, et vérifie qu'il n'atteint
  pas la simulation, que le même parcours atteint bien depuis le tick du runtime (C-40).

Les deux tests ont été vérifiés par mutation : un `Class.forName` dans le lecteur, un appel à
`dev.axion.physics` depuis `tick()`, les font échouer.

## Conséquences

- Les trois plages de M2 sont attribuées. Au prononcé de M2, le jalon entre dans `COMPLETED_MILESTONES` et
  `MilestoneTestsCoveredTest` vérifie dès lors la présence de chaque numéro.
- Un test ajouté plus tard à un groupe en reprend le numéro ; un test qui changerait ce que prouve un
  groupe passe par un amendement de cette table.
