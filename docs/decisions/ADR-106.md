# ADR-106 — Tangentes et cache de sommets : les bibliothèques de la table 32.2, et ce que R-553 en exige

- **Statut** : accepté
- **Date** : 2026-09-13
- **Portée** : C-23 (étapes 3 et 5), R-553, R-1640, R-2290, R-2300, R-2301, PARTIE 32.2
- **Décidé par** : Claude, en écrivant la tranche B de l'optimizer

## Contexte

La fiche C-23 impose des tangentes **MikkTSpace** (étape 3) et un cache de
sommets **Forsyth** (étape 5). La table 32.2 retient pour cela `mikktspace` et
`meshopt`, avec « implémentation propre » et « Forsyth propre » comme
alternatives évaluées.

La tranche A a écarté toute fonction de `libm` pour que la fusion et les
normales soient identiques au bit près **d'une plateforme à l'autre**. Les deux
bibliothèques ne le garantissent pas :

- `mikktspace` 0.3.0 est une transcription du C d'origine qui pondère par
  `acos`, donc par la `libm` de la plateforme ;
- `meshopt` 0.6.2 compile meshoptimizer 0.25 en C++. Selon le compilateur et ses
  options, `a * b + c` peut y être contracté en FMA sur une plateforme et pas
  sur l'autre.

Toutes deux sont en revanche **déterministes sur une même plateforme** : graine
de tri fixe (`39871946`) dans `mikktspace`, aucun aléa ni fil d'exécution dans
meshoptimizer. Vérifié en lisant les sources des versions retenues.

## Ce que R-553 exige ici

R-553 : « mêmes entrées et même version → même sortie bit à bit ». Deux lectures
sont possibles : sur une machine donnée, ou entre toutes les machines.

La seconde ne sert qu'à une sortie **comparée entre machines**. R-1640 tranche
pour les assets : ils **ne transitent jamais par le réseau**, chaque machine les
compile depuis ses resource packs, et le serveur ne compare les empreintes que
des definitions, matériaux et sources de dégâts. Tangentes et ordre des indices
ne servent qu'au rendu, qui n'est jamais répliqué.

## Décision

1. **`mikktspace` et `meshopt` sont retenus**, comme le veut la table 32.2.
   MikkTSpace doit être *la* référence : une normal map cuite par Blender se lit
   dans l'espace tangent où elle a été cuite, et une réécriture qui en
   divergerait éclairerait faux toutes les cartes du marché. Le code transcrit
   est vérifié par l'usage de l'écosystème glTF ; une réécriture ne le serait
   que par nos tests.

2. **R-553 s'applique ici plateforme par plateforme.** Pour les étapes 3 et 5,
   la garantie est : même entrée, même version, même plateforme → même sortie.
   T-243 le vérifie.

3. **La garantie entre plateformes reste due partout où une sortie de C-23
   entre dans la simulation.** Ce sera le cas des points d'enveloppe et de la
   décomposition convexe (étapes 8 et 9, R-551), dont la physique dépend. Ces
   étapes n'emploieront ni `libm` ni code C++ compilé sans contrôle de ses
   options flottantes, ou le justifieront par un ADR.

4. **`mikktspace` est pris avec la fonctionnalité `glam`** plutôt que
   `nalgebra`, fonctionnalité par défaut : le crate n'en utilise que les types
   vecteurs, et `glam` 0.15 n'a aucune dépendance. Il coexiste avec le `glam`
   0.33 d'AXION. `meshopt` ajoute de même une seconde version de `float-cmp` et
   de `thiserror`. `cargo deny check` le constate et `deny.toml` signale ces
   doublons sans bloquer, comme les autres doublons transitifs ; avis RustSec,
   licences et sources restent conformes.

5. **Licences.** La table 32.2 annonce Zlib pour `mikktspace`. Le crate est
   sous **MIT OR Apache-2.0** ; c'est le code C d'origine, de Morten S.
   Mikkelsen, qui est sous zlib. `meshopt` est sous MIT OR Apache-2.0 et embarque
   meshoptimizer, d'Arseny Kapoulkine, sous MIT. Ces deux codes embarqués ne
   se lisent pas dans les métadonnées cargo : `tools/deps/gen_notice.py` les
   attribue explicitement dans le `NOTICE` (R-2290). La table n'est pas
   corrigée, le cahier des charges étant gelé ; ce fichier fait foi.

## Alternatives évaluées

- **Implémentations propres, en arithmétique IEEE exacte.** Elles donneraient la
  garantie entre plateformes, dont aucune sortie de rendu n'a l'usage (R-1640).
  Le cache de Forsyth tient en deux cents lignes ; MikkTSpace en compte près de
  deux mille, et sa valeur tient entièrement à sa conformité avec la
  référence. Écartées pour ces deux étapes, et pour cette raison seulement.
- **`nalgebra` pour `mikktspace`.** Écarté : une dizaine de dépendances pour
  trois types vecteurs.

## Conséquences

- Un compilateur C++ est requis pour construire la bibliothèque native. Les
  runners de la CI en fournissent un sur les trois systèmes ; un développeur
  sous Windows l'a avec les Build Tools de Visual Studio, déjà nécessaires à
  l'éditeur de liens MSVC.
- Deux machines de plateformes différentes peuvent produire des `.a3d` dont les
  tangentes diffèrent de quelques pas de quantification. C'est sans effet sur la
  simulation et sur le réseau ; un `.a3d` précompilé (R-861) reste identique
  pour tous, puisqu'il n'est compilé qu'une fois.
- Si un jour une empreinte d'asset devait être comparée entre machines, cette
  décision serait à reprendre avant.
