# ADR-161 — L'organisation du dépôt

- **Statut** : **accepté** le 2026-11-10 par Killian : « le workspace est un bazar complet, on s'y perd », plan
  proposé validé en entier, guides rangés dans `docs/` avec le CDC amendé.
- **Date** : 2026-11-10
- **Portée** : l'arborescence du dépôt, les chemins des tâches Gradle, de la CI et des outils ; PARTIE 33 du CDC
  (documentation racine).

## Contexte

Ce qui gênait Killian : trop de dossiers à la racine, ne pas savoir où est quoi, trop de fichiers au même endroit.
Le constat :

- **Neuf dossiers de jeu à la racine** (`run`, `run-campagne`, `run-data`, `run-film`, `run-gametest`,
  `run-rendertest`, `run-rendertest-native`, `run-rendertest-shaders`, `run-server`), un par tâche Gradle, environ
  3,2 Go à eux tous, ignorés par Git mais visibles partout.
- **La racine mêle** les guides (`PHYSICS.md`, `RENDERING.md`, `MATERIALS.md`, `CONFIGURATION.md`), le build, les
  consignes des agents et la licence.
- **Le CDC est seul dans `cdc/`**, loin de son index (`docs/spec/`) et des ADR (`docs/decisions/`).
- **61 ADR à plat**, sans plan.
- **`docs/3d model/`**, le modèle local de la Charger, avec un espace dans le nom, au milieu de la doc.
- **`src/devcontent`** mêle le contenu des tests, celui des films et le contenu local.
- **Aucun plan du dépôt, aucun README par dossier.**

Ce qui ne s'aplatit pas : la profondeur `java/axion-mod/src/main/java/dev/axion/…` est celle de Java et de Gradle ;
les fichiers de build restent à la racine, où Gradle et Cargo les cherchent.

## Décision

### D1 — L'arborescence cible

```
AXIONENGINE/
├── README.md  LICENSE  NOTICE  CHANGELOG.md   accueil et plan du dépôt
├── CLAUDE.md  AGENTS.md                       consignes des agents
├── build.gradle  settings.gradle  Cargo.toml  …  build (imposé à la racine)
├── java/          axion-api, axion-mod
├── crates/        le moteur natif Rust
├── content/       exemples, contenu de test et de film (avec l'API d'enregistrement, D3)
├── docs/
│   ├── spec/        le CDC et son index
│   ├── decisions/   les ADR et un README qui les range par jalon et par sujet
│   ├── guides/      PHYSICS, RENDERING, MATERIALS, CONFIGURATION
│   └── schema/
├── tools/  fuzz/  benchmarks/  third_party/
├── local/         ignoré par Git : modèles et contenu personnels (la Charger)
└── .runs/         ignoré par Git : un dossier de jeu par tâche
```

### D2 — Les dossiers de jeu

| Avant | Après | Tâche |
|---|---|---|
| `run/` | `.runs/client/` | `runClient` |
| `run-server/` | `.runs/server/` | `runServer` |
| `run-gametest/` | `.runs/gametest/` | `runGameTestServer` |
| `run-film/` | `.runs/film/` | `runFilmVehicule` |
| `run-rendertest/` | `.runs/rendertest/` | `runRenderTest` |
| `run-rendertest-native/` | `.runs/rendertest-native/` | `runRenderTestNative` |
| `run-rendertest-shaders/` | `.runs/rendertest-shaders/` | `runRenderTestShaders` |
| `run-data/` | `.runs/data/` | `runData` |
| `run-campagne/` | `.runs/campagne/` | `tools/campagne` |

Les dossiers existants sont déplacés, pas recréés : leurs réglages (narrateur coupé, son à zéro) suivent. Les ADR
et le plan écrits avant cette date gardent les anciens chemins dans leurs récits ; cette table les traduit.

### D3 — Le contenu

`content/` naît avec le code de l'API d'enregistrement (ADR-160 D9, D10) : ce chantier réécrit justement la façon
dont les exemples, le contenu de test et celui des films sont chargés. Les déplacer avant, ce serait les déplacer
deux fois. D'ici là, seul le contenu local quitte `src/devcontent` pour `local/`.

### D4 — La documentation

Le CDC passe de `cdc/` à `docs/spec/`, à côté de son index. Les quatre guides passent de la racine à
`docs/guides/` ; la PARTIE 33 du CDC est amendée en conséquence (registre 38.9). Chaque dossier de premier niveau a
un `README.md` d'une phrase ou deux : ce qu'il contient, ce qu'on y cherche. `README.md` à la racine porte le plan
du dépôt. `docs/decisions/README.md` range les ADR par jalon et par sujet ; les fichiers restent à plat, leurs
chemins étant cités partout (code, ADR, plan, commits).

### D5 — Ce qui reste à voir

« Trop de fichiers au même endroit » vaut aussi pour le code : 60 types dans `dev.axion.api`, 45 classes dans
`dev.axion.render`. Le découpage de l'API en paquets (`dev.axion.api.vehicle`, `….event`…) se décide dans l'ADR de
l'API d'enregistrement, tant qu'elle est `@Experimental` ; celui des paquets internes, au fil des chantiers qui les
touchent.

## Conséquences

- Chaque étape est un commit à part, vérifié par la CI locale ; le banc de rendu passe une fois, à la fin, puisque
  des chemins de jeu changent.
- `CLAUDE.md`, `docs/AGENT.md`, les outils de spec et la mémoire des agents suivent les nouveaux chemins.
